# 审查报告格式

# Skill 结构审查报告

## 总结

发现：

- 术语一致性：X
- 步骤边界：X
- 执行路由：X
- 状态流转：X

关键风险：

- ...
- ...

## 问题清单

### [编号] 简短标题

**级别：** 高 | 中 | 低

**问题**  
用一小段话说明结构问题。

**证据**  
优先使用 `path/to/file.md:42-51`。

如无法获得稳定行号，则使用：

- 文件 + 章节/标题
- 文件 + 字段
- 文件 + 精确术语

证据必须足以让维护者直接定位问题。

**影响**  
说明可能造成的执行、维护、路由、恢复或一致性问题。

**建议**  
给出解决该问题所需的最小改动。

只输出有明确证据的问题。

## 建议修改顺序

1. 先修复可能导致错误执行或状态漂移的问题。
2. 再修复路由和步骤边界问题。
3. 再统一术语并清理历史名称。
4. 最后处理低风险清理项。

## 报告规则

- 无证据，不下结论。
- 不输出泛化建议。
- 不计算综合评分。
- 不扩展到四个审查范围之外。
- 优先报告少量高价值问题，不追求穷举所有细枝末节。
